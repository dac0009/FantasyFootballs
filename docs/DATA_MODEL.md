# Data model

Everything in `data/` is generated by `python -m pipeline refresh` (or `sample`). Nothing in it
is hand-edited. Regenerating is always safe.

## Files

| File | Contents | Loaded by |
|---|---|---|
| `meta.json` | Schema/pipeline version, generation time, source (`espn` or `sample`), season list, counts, documented limitations, validation warnings | every page |
| `manifest.json` | Byte size of every generated file | nothing; diagnostics |
| `seasons.json` | One row per season: team count, schedule length, champion, runner-up | archive index |
| `seasons/{year}.json` | A whole season: standings, every week, bracket, champion, weekly series, leaders, limitations | season and week pages |
| `owners.json` | One row per owner: career totals and the team-name timeline | owners index, pickers |
| `owners/{owner_id}.json` | Full profile: season-by-season, head-to-head summary, highs and lows, lineup efficiency, every game | owner page |
| `matchups.json` | Every matchup, all seasons | — |
| `team_weeks.json` | Every team-week (two rows per completed matchup) | — |
| `records.json` | The record book, grouped by scope | records page |
| `head_to_head.json` | Every owner pair, keyed `ownerA__ownerB` (sorted), including all meetings | head-to-head page |
| `current.json` | Homepage payload: latest week, standings, milestones, movement | homepage |
| `game_of_week.json` | The pick, its component scores, and the ranked candidates | homepage |
| `players.json` | Player index: id, name, position, NFL team | week, draft pages |
| `drafts/{year}.json` | Draft picks | draft page |
| `rosters/{year}.json` | Per-week lineup rows | week page |
| `transactions/{year}.json` | Adds, drops, waivers, trades — **only when ESPN provides them** | — |

`matchups.json` and `team_weeks.json` are the raw normalized tables. The site mostly reads the
pre-assembled per-season and per-owner payloads instead, but these are published so the data is
usable from a notebook or a script without re-running the pipeline.

## Core tables

### `team_week` — the atom of the system

One row per team per completed game. Almost every statistic is a function of these rows.

| Field | Notes |
|---|---|
| `season`, `week` | `week` is ESPN's `matchupPeriodId` |
| `matchup_id` | `{season}-{week}-{lowTeamId}-{highTeamId}` |
| `game_type` | `regular`, `playoff`, `consolation`, `postseason_other` |
| `team_id` | ESPN's per-season team id. **Reused across seasons — not an identity** |
| `owner_id` | The stable identity. Use this for anything career-scoped |
| `team_name` | As it was *that season* |
| `score`, `opponent_score`, `differential` | |
| `result` | `W`, `L`, `T` — derived from the scores, never from ESPN's flag |
| `opponent_team_id`, `opponent_owner_id`, `opponent_team_name` | |
| `is_home` | |

Only completed games appear here. Incomplete games live in `matchups.json` with
`completed: false`.

### `matchup`

One row per scheduled game, completed or not. Carries `is_bye` for playoff byes (one side only,
never counted), `winner` as ESPN reported it, and `margin`/`combined` which are `null` until the
game is complete.

### `owner`

| Field | Notes |
|---|---|
| `owner_id` | Slug from the person's name; the URL segment |
| `name` | Display name, from ESPN or pinned in `config/owners.yml` |
| `member_hash` | Salted hash of the ESPN member GUID. **The raw GUID is never published** |
| `seasons` | Seasons played |
| `team_name_timeline` | `[{season, team_id, team_name, abbrev}]` |
| `unlinked` | `true` when ESPN gave no member account for this team |

## Game type classification

The rule, in order:

1. `week <= regular_season_weeks` → `regular`
2. `playoffTierType == "WINNERS_BRACKET"` → `playoff`
3. `playoffTierType` in the consolation set → `consolation`
4. Postseason week with no usable tier flag (older seasons): if both teams' playoff seeds are
   within the bracket → `playoff`, else `consolation`
5. Otherwise `postseason_other`, and the validator warns

`regular_season_weeks` comes from `settings.scheduleSettings.matchupPeriodCount`, which in
ESPN's model is the count of *regular season* matchup periods. When it is absent, it is inferred
from the first week carrying a bracket flag.

## Conventions

- Scores are rounded to 2 decimal places; rates to 3.
- `null` means "not available", never `0`.
- NaN and infinity are impossible: `write_json` uses `allow_nan=False`, so a NaN raises rather
  than producing invalid JSON that fails silently in the browser.
- Lists are deterministically ordered, so regenerating unchanged data produces no git diff.

## Changing the schema

Bump `SCHEMA_VERSION` in `pipeline/config.py`, update `web/src/lib/types.ts`, and update this
file. The frontend reads `meta.schema_version`, so a mismatch is detectable.
